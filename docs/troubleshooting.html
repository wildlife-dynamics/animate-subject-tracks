Troubleshooting

Common issues encountered while configuring, running, or contributing to the Animate Subject Tracks Workflow, and how to resolve them. If your issue isn't listed here, open an issue on GitHub.

Data & Configuration

The run finishes but the map is empty, or no files are written

The Subject Group Name must match the group name in EarthRanger exactly, and the group must have location fixes inside the Time Range. The workflow doesn't raise an error when EarthRanger returns nothing: the empty result causes every later step to be skipped instead, so you get an empty run rather than a failure.

Some fixes are missing from a track

Only fixes that are not marked as excluded in EarthRanger are fetched. Fixes at the known junk coordinates (0, 0), (1, 1) and (180, 90) are also dropped.

A track is broken into disconnected pieces, or a subject is missing entirely

The Trajectory Segment Filter drops segments longer than 100 km, longer than 2 days, or faster than 500 km/h (among other limits). Data with long gaps between fixes, or GPS glitches, can lose segments. If every segment of a subject is dropped, that subject disappears. Loosen the limits to match your data's fix interval and speeds.

Unexpected results with a mixed group

Groups that mix subject subtypes (e.g. collared animals and vehicles) can give unexpected results: a single segment filter has to suit all of them, and the automatic framing covers every subject. Animate one subtype per run where possible.

Map & Terrain

The terrain or satellite imagery is blank

Terrain elevation (AWS Terrarium) and imagery (Esri World Imagery) tiles are fetched live, by the workflow while it runs and by the browser when you open the map. Check that the machine, and anyone viewing animated_map.html, has internet access and can reach s3.amazonaws.com and server.arcgisonline.com.

Trails float above the terrain or disappear into it

Adjust Terrain Sampling → Offset (default 30 m above the ground). If elevation tiles couldn't be read during the run, every track point is placed at the constant Ground Elevation (default 1000 m), which won't match the real terrain; re-run once the tiles are reachable. Changing Terrain Exaggeration re-drapes the trails to match automatically.

The map is framed badly, or looks flat

The view is fitted to all tracks automatically. To see the terrain in 3D, raise Pitch (e.g. 45–60) and optionally rotate with Bearing. One subject far from the rest will make the automatic framing zoom out to include it.

The 3D model marker doesn't appear, or faces the wrong way

Check the Marker icon setting. For a custom model, the GLB URL or file must be reachable from the machine running the workflow. If the model faces sideways, adjust Yaw Offset; if it is nose-up or nose-down, adjust Model Pitch. If it spins or tips while the subject is stationary, raise Min Move M or leave Terrain Pitch off.

Video

The run is slow, mostly at the video step

The video is recorded frame by frame: frames = 30 fps × duration. The default is 900 frames at 720p. 1080p, 4K and longer durations take proportionally longer. Try the defaults first. Machines without a GPU fall back to software rendering, which is much slower.

The first video render fails with a browser or Playwright error

On its first run in a new environment, the video step downloads Playwright's Chromium browser. The machine needs internet access and permission to write to its Playwright cache. Run the workflow again once that's resolved.

camera='keyframes' needs at least 2 keyframes

A Keyframes camera path needs at least two waypoints. Add more rows to your waypoint file, or leave the keyframes empty and choose Follow a subject as the source to derive a path from the data.

Keyframes waypoint file is rejected

Supported formats are .json (a list of objects with lon/lat), .geojson (Point features), .csv and .tsv (lon/lat columns; longitude/latitude, lng or x/y also work). Optional columns: t, zoom, pitch, bearing (or heading).

No outputs written / can't find results

All outputs are written to the directory specified by the ECOSCOPE_WORKFLOWS_RESULTS environment variable. Confirm it's set and points to a directory the workflow process can write to. The video is saved there as animation.mp4; it isn't shown on the dashboard.

Contributing & CI

These apply if you're modifying the workflow itself (spec.yaml or the generated ecoscope-workflows-animate-tracks-workflow/ directory) and opening a pull request.

Generated files differ from committed files in ecoscope-workflows-animate-tracks-workflow

The generated workflow directory is out of sync with spec.yaml. Run the recompile script locally and commit the result:

pixi run --manifest-path pixi.toml --locked bash -c "./dev/recompile.sh --update"

Found wildcard version (*) in requirements or Found local file channel (file://) in requirements

In spec.yaml, every dependency under requirements must pin a version and use a remote conda channel. Wildcard versions and local file:// channels (e.g. a local build of ecoscope-workflows-ext-mep) are only for local development.

VERSION.yaml (...) must be greater than main branch (...)

Bump MAJ/MIN/PATCH in ecoscope-workflows-animate-tracks-workflow/VERSION.yaml so it's strictly greater than the version on main before opening or updating a PR.

test-cases.yaml not found or test-cases.yaml must contain at least one test case

Every workflow needs a test-cases.yaml at the repository root with at least one top-level entry containing a params block.

Documentation changes don't appear on the site

The site is deployed from the docs/ folder by the Deploy Pages workflow on every push to main that touches docs/. After changing spec.yaml, regenerate the technical guide and copy it into the site:

cd technical_guide && python3 generate_technical_guide.py
cp animate_subject_tracks_technical_guide.pdf ../docs/assets/
